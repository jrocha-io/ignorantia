# API reference

The v3 codebase is documented inline (Google-style docstrings) and
the pages under this section are auto-generated by
[mkdocstrings](https://mkdocstrings.github.io/) from those
docstrings. To rebuild locally:

```bash
pip install -e '.[docs]'
mkdocs build       # static site → site/
mkdocs serve       # dev server → http://127.0.0.1:8000/
```

## Layout

| Layer | Modules |
|---|---|
| `domain/` | [audit](domain_audit.md) · [compliance](domain_compliance.md) · [pipeline](domain_pipeline.md) · [render](domain_render.md) · [search](domain_search.md) |
| `application/` | [Application use cases + DTOs](application.md) |
| `interface/` | [Click CLI + JSON-schema validators](interface.md) |
| `legacy/` | [v2 compatibility shim](legacy.md) |

The `infrastructure/` layer is intentionally omitted from the
auto-generated reference: each adapter is a Strategy implementation
of a port already documented under `domain/<context>/ports/`. To
inspect a specific concrete adapter, read its file directly.

## Stability

Public surface (the union of all classes / functions documented
under `domain/`, `application/`, `interface.cli.main`,
`interface.manifests`, `legacy`) follows SemVer. Breaking changes
will land only on a major bump and will be called out in the
[migration guide](../MIGRATION_v2_TO_v3.md) before the release.
